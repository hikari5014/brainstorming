Subscription-Backed LLM Proxy

Use a paid Claude Code (or Gemini Web) subscription as the LLM backend for your own apps — without buying a separate API key. Local proxy, OpenAI-shape API, single user.

1. Problem & Motivation

Anthropic and Google sell two things under one brand:

  • Subscriptions (Claude Code, Gemini Advanced) — flat monthly fee, unlimited-ish conversational use through the official UI/CLI, tied to a single logged-in user.
  • API quota (Anthropic API, Gemini API) — pay-per-token, separately billed, the only thing officially blessed for embedding into your own applications.

If you already pay for the subscription, the marginal cost of one more prompt is zero. Buying API quota on top of it to power a personal side project feels like paying twice. This doc is about closing that gap — letting your app spend the subscription's daily/5-hour budget instead.

Scope. Personal-use, single-user, 127.0.0.1 only. This is not a SaaS multiplexer — that would violate the per-user license of every consumer subscription on the planet.

2. Architecture

A local FastAPI proxy speaks OpenAI's /v1/chat/completions shape, and an adapter layer translates each request into a claude -p --output-format json subprocess call. Batch jobs land in a SQLite queue and a worker drains them one at a time, respecting the 5-hour rolling rate limit.

Why two processes?

  • Server stays responsive for interactive calls even when a batch is in flight.
  • Worker can sleep on rate-limit backoff without freezing the API.
  • SQLite (WAL) keeps the moving parts honest — restart either side without losing jobs.

Why subprocess instead of an SDK?

Anthropic publishes @anthropic-ai/sdk and anthropic (Python) — but those require a separate API key. Claude Code's subscription auth lives in the local OAuth keychain and is consumed by the claude binary itself. The supported way to leverage it programmatically today is to shell out.

Why claude -p isn't a ToS landmine the way Gemini-Web is

Anthropic ships --print, --output-format json, --session-id and --disallowedTools as first-class flags and documents them in claude --help. Running the CLI from a subprocess is mechanically identical to a user typing in a terminal. What would breach the license is re-selling the resulting capacity (multi-tenant SaaS, shared API key for a team without per-seat purchase, etc.). This PoC binds to loopback and ships with no auth on purpose.

5. Integration Patterns

A. Subprocess CLI

+ Official, supported, stable flags.

+ Auth is free — inherits OAuth from the user's machine.

+ Easy to sandbox tools with --disallowedTools.

− One process per call (~80 ms overhead).

− Streaming requires stream-json + reshaping.

B. Browser automation

+ Works for Gemini Web / ChatGPT / Claude.ai equally.

+ Visual debugging via headed mode.

− Selectors rot with every UI release.

− CAPTCHA + bot-detection eventually triggers.

− Slow (seconds per call, browser warmup).

C. Reverse REST

+ Faster than headed browser; close to API latency.

+ Easy to multiplex calls.

− Internal endpoints break silently.

− Cookie/SAPISID rotation is annoying.

− Most clearly ToS-adjacent.

7. PoC Walkthrough

Three copy-pasteable cURLs against the proxy on 127.0.0.1:8765.

Sync call

curl -s http://127.0.0.1:8765/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{
    "model": "haiku",
    "messages": [
      {"role": "user", "content": "Reply with the single word PONG"}
    ]
  }' | jq

Multi-turn (session resumed via --resume)

curl -s http://127.0.0.1:8765/v1/chat/completions \
  -H 'content-type: application/json' \
  -H 'X-Conversation-Id: my-convo-42' \
  -d '{
    "model": "sonnet",
    "messages": [{"role":"user","content":"Remember the codeword: cherry"}]
  }'

# later, same X-Conversation-Id reuses the underlying --session-id
curl -s http://127.0.0.1:8765/v1/chat/completions \
  -H 'content-type: application/json' \
  -H 'X-Conversation-Id: my-convo-42' \
  -d '{
    "model": "sonnet",
    "messages": [{"role":"user","content":"What was the codeword?"}]
  }'

Batch submit + poll

BID=$(curl -s http://127.0.0.1:8765/v1/batches \
  -H 'content-type: application/json' \
  -d '{"requests":[
    {"model":"haiku","messages":[{"role":"user","content":"Summarize: tcp/ip"}]},
    {"model":"haiku","messages":[{"role":"user","content":"Summarize: http/2"}]},
    {"model":"haiku","messages":[{"role":"user","content":"Summarize: quic"}]}
  ]}' | jq -r .id)

# in another shell:  ./run.sh worker
curl -s http://127.0.0.1:8765/v1/batches/$BID | jq

End-to-end smoke test (no real quota)

./run.sh setup
./run.sh test          # uses POC_FAKE_BACKEND=1 by default
POC_FAKE_BACKEND=0 ./run.sh test   # exercise the real CLI

8. Out of scope / Future

  • Real Gemini Web adapter — Playwright cookie capture, headed first-run, CAPTCHA handling. Acceptable for personal use with eyes open.
  • SSE streaming — wrap --output-format stream-json --verbose into OpenAI data: {...} frames.
  • Tool / function calling — translate OpenAI tools[] into Claude tool use; right now --disallowedTools turns them all off.
  • Persistent conversation map — currently in-memory; restart drops the convo → session_id table.
  • Cost ledger — beyond pass-through of --max-budget-usd.
  • Multi-user auth — explicitly never. The personal license forbids it; if you need it, buy the API.
